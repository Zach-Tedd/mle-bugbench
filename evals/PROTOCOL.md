# Evaluation protocol: do AI assistants catch ML leakage?

**Question:** when asked to work on leaky ML code, do AI coding assistants catch the leak on their own (neutral prompt), or only when told to look for problems (review prompt)?

## Conditions

| Condition | What the assistant is told |
|---|---|
| `neutral` | The scenario, then "Please improve this model and give me the complete updated solution.py." No hint that anything is wrong. |
| `review` | The scenario, then the task's review instruction: "Review it, fix every problem that makes the reported performance untrustworthy…" |

Both prompts include the same `data.py`, starter `solution.py`, and interface table, and are generated by `bugbench.prompt`. The neutral prompt's interface table describes `notes` neutrally, so it carries no hint.

## Rules for every run

1. **New chat for every run.** No memory, custom instructions or files from earlier chats. Turn off memory or personalisation if the app has it.
2. **Paste the prompt exactly** as generated: `uv run python -m bugbench.prompt t01 neutral | clip.exe`, then paste.
3. **One turn only.** No follow-up questions, no "are you sure?", no retries. Whatever comes back first is the answer.
4. **Default settings.** Use the app's default model unless the run is about a specific model; no extra tools enabled beyond the defaults.
5. **Take the first complete Python code block** that defines `run(...)`, unchanged, and save it as `evals/runs/<assistant>/<task>_<condition>.py` (for example `evals/runs/claude/t01_neutral.py`).
6. **If there is no usable code block**, save a file containing only `raise RuntimeError("no code returned")`, so the run counts as a failure rather than disappearing.
7. **Read the code before grading.** It is model-written and runs with your permissions.
8. **Record the run** in `evals/runs/<assistant>/meta.json`: the model name shown in the app, the interface (web/desktop app), and the date.

```json
{"model": "<name shown in the app>", "interface": "web chat", "date": "2026-11-20"}
```

## Grading

```bash
uv run python -m bugbench.evaluate     # writes evals/results.csv and evals/results.md
```

Each answer is graded in its own process with a 15-minute limit. A crash or timeout scores 0 and is recorded as an error.

## What this can and can't show

- One run per cell, at default settings: assistants are not deterministic, so a single pass or fail is an observation, not a rate. Repeat runs are needed before claiming a rate for any one task.
- Results describe the models and app versions on the recorded dates; they will change.
- The tasks are synthetic and their reference solutions are public, so a model may have seen similar material.
